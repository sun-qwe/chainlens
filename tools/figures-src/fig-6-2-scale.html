节点规模—管线耗时曲线

解析 + 布局 + 渲染合计（中位数）

规模实验结论

1. 增长趋势
节点数从 66 增至 260（约 3.9 倍），管线耗时从 7.7 ms 增至 23.3 ms（约 3.0 倍），近似线性，未出现平方级膨胀。主要增长来自 SVG 节点/边 DOM 的创建与样式计算（渲染 4.3 → 14.5 ms）。

2. 设计目标对照
NFR-01 要求 260 节点 / 320 关系首屏 < 1 s。实测页面首屏 80 ms、管线 23.3 ms，均远低于目标；1366×768 下同样无横向溢出。

3. 瓶颈定位
解析与布局合计仅 8.9 ms（260 节点），渲染占比约 62%。后续若扩展到千级节点，应优先优化 SVG 绘制（虚拟化、Canvas/WebGL、边简化），而非布局算法。

4. 降级策略
节点超过 600 时隐藏边标签与部分动画；默认缩放不低于 0.7，保证可读字号；用户可点"适配"查看全貌，或通过筛选聚焦子图。

5. 可复现性
数据由固定 seed 生成；实验在 headless Chrome 157、1600×1000 下完成，三次采样取中位数；bench 接口不产生 UI 副作用。
