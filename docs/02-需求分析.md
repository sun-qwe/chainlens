# ChainLens 需求分析

## 1. 业务背景与问题

渗透测试的价值不仅在于"发现漏洞"，更在于**过程可追溯、结论可复核、经验可复用**。在 DSH 智能体环境中，`dsh-pentest` 插件让智能体按授权范围执行测试，但会产生三类问题：

1. **过程黑箱**：智能体的工具调用、资产发现、验证动作散落在日志与对话中，无法整体回看；
2. **数据异构**：资产、服务、漏洞、凭据、会话、证据、时间戳混在一起，缺少统一模型；
3. **结论难复现**：报告只给结果，无法回答"这条路径是怎么走通的、风险为什么高"。

因此需要一套面向探索链路的可视化分析工具，把"过程数据"变成"可读、可查、可回放、可报告"的分析对象。

## 2. 用户角色与使用场景

| 角色 | 关注点 | 典型操作 |
|---|---|---|
| 渗透测试人员 | 测试过程是否完整、哪条路径风险最高 | 导入一次测试的 JSONL，查看链路图、关键路径、证据完整性 |
| 安全评审/导师 | 测试是否在授权范围内、结论是否有证据 | 查看授权信息、范围、证据链、风险发现与建议，导出报告 |
| 智能体开发者 | 插件记录的数据格式是否合理、哪一步丢数据 | 用仿真数据验证 schema、导入校验、回放定位异常事件 |
| 学习者 | 理解一次渗透测试的完整流程 | 回放时间线、ATT&CK 矩阵、按阶段查看资产与动作 |

## 3. 功能需求

### 3.1 数据采集与接入（FR-1）

- FR-1.1 插件提供 `pentest_start_engagement`，记录授权依据、范围、模式、操作者；
- FR-1.2 插件提供 `pentest_record_step`，支持 node/edge/event/evidence/note 五类记录；
- FR-1.3 插件对 scope、授权、敏感字段做校验与脱敏；
- FR-1.4 提供仿真数据生成命令，三种规模场景可复现；
- FR-1.5 可视化端支持 JSONL/JSON 文件拖拽导入，坏行容错并展示校验结果；
- FR-1.6 支持从 `manifest.json` 加载内置场景。

### 3.2 总览（FR-2）

- FR-2.1 展示测试会话基本信息（名称、模式、范围、授权、时间）；
- FR-2.2 展示节点/边/事件/漏洞/证据/风险/阶段覆盖等 KPI；
- FR-2.3 展示阶段分布、严重度分布、事件时间密度、节点类型排行；
- FR-2.4 给出关键路径摘要与 Top 风险节点，可跳转到链路图。

### 3.3 探索链路图（FR-3）

- FR-3.1 按阶段分列展示节点与关系，节点类型可区分；
- FR-3.2 支持缩放、平移、节点拖拽、适配屏幕、重置；
- FR-3.3 支持按阶段、类型、严重度、关键词筛选，筛选后重排；
- FR-3.4 支持选中节点查看详情与一跳邻居聚焦；
- FR-3.5 支持风险加权关键路径计算与高亮；
- FR-3.6 支持按时间回放，逐步显示节点/边与当前事件；
- FR-3.7 展示节点数、边数、布局耗时等性能提示（调试用）。

### 3.4 时间线回放（FR-4）

- FR-4.1 按阶段泳道展示事件，位置与时间成比例；
- FR-4.2 支持播放/暂停、上一条/下一条、进度拖动、倍速；
- FR-4.3 显示当前事件摘要与关联对象；
- FR-4.4 显示各阶段耗时、成功率、最长静默间隔。

### 3.5 ATT&CK 覆盖矩阵（FR-5）

- FR-5.1 按战术列、技术行展示出现频次热力矩阵；
- FR-5.2 显示战术/技术覆盖数；
- FR-5.3 点击单元格筛选并列出命中事件。

### 3.6 发现与证据（FR-6）

- FR-6.1 风险发现列表：严重度、CVSS、标题、资产、阶段、状态、证据数；
- FR-6.2 证据库：类型、标题、关联节点、时间、敏感打码；
- FR-6.3 支持排序、筛选、搜索；导出 CSV/JSON；
- FR-6.4 详情抽屉显示完整字段与修复建议。

### 3.7 分析报告（FR-7）

- FR-7.1 自动生成执行摘要、范围与授权、指标表、阶段推进、关键路径、Top 发现、ATT&CK 覆盖、证据清单、数据质量说明；
- FR-7.2 支持打印/另存 PDF，A4 排版；
- FR-7.3 报告内容与当前筛选/数据一致，无占位符。

### 3.8 通用交互（FR-8）

- FR-8.1 深链可复现视图状态；
- FR-8.2 顶部场景切换、导入、导出、主题；
- FR-8.3 加载态、空态、错误态、toast 提示；
- FR-8.4 Esc 关闭抽屉/弹窗，键盘可达。

## 4. 非功能需求

| 类别 | 指标 | 说明 |
|---|---|---|
| 性能 | 260 节点/500 边首屏 < 1.5s；布局 < 200ms；回放 60fps 目标 | 1366×768 笔记本，Chrome/Edge |
| 兼容 | Chrome/Edge 最近两个大版本；1366×768 至 2560×1440 | 答辩投影常见分辨率 |
| 可用性 | 核心任务 ≤ 3 次点击；关键状态有视觉反馈 | 场景走查 |
| 可靠性 | 单条坏数据不导致崩溃；导入失败可恢复 | 容错 |
| 安全 | 无外部网络请求；敏感证据默认打码 | 数据不出本机 |
| 可维护 | 单文件 < 900 行；算法与 DOM 解耦；单测覆盖核心算法 | 工程质量 |
| 可移植 | 零第三方依赖、零构建；Python 3.10+ 静态服务即可运行 | 降低演示风险 |

## 5. 用例描述（节选）

**UC-01 查看一次测试的探索链路**

- 参与者：渗透测试人员
- 前置：已有 `chain.jsonl` 或打开内置场景
- 主流程：选择场景 → 总览查看 KPI → 进入链路图 → 点击漏洞节点查看详情与证据 → 打开关键路径 → 进入报告页导出 PDF
- 异常：数据缺失/格式错误 → 显示错误面板与行号，允许修复后重新导入

**UC-02 回放测试过程**

- 参与者：学习者/评审
- 主流程：进入时间线视图 → 播放 → 观察阶段推进与事件 → 在关键事件处暂停 → 跳到链路图查看当时子图
- 异常：事件时间相同 → 按 seq 排序，保证顺序稳定

**UC-03 用仿真数据验证插件记录**

- 参与者：智能体开发者
- 主流程：运行 `dsh-pentest demo` → 校验 JSONL → 可视化导入 → 检查节点/边/事件是否完整 → 如缺失则定位阶段
- 异常：校验失败 → CLI 输出错误行号与原因

## 6. 需求优先级

| 优先级 | 需求 |
|---|---|
| P0 | FR-1.1~1.6、FR-2、FR-3.1~3.6、FR-4、FR-6、FR-7.1 |
| P1 | FR-3.7、FR-5、FR-7.2、FR-8.1 |
| P2 | 主题切换、报告 Markdown 复制、批量对比、实时推送 |

## 7. 验收标准

1. 插件 `node --test` 全部通过，`demo` 三场景可复现生成并通过独立校验；
2. 可视化端三场景六视图可用，无未捕获异常；
3. 260 节点场景首屏 < 1.5s（本机实测数据写入论文）；
4. 关键路径、筛选、回放、详情、导入、导出、打印均可用；
5. 报告无占位符，数据与当前场景一致；
6. 无外部网络请求，敏感证据默认打码；
7. README/使用说明能让陌生用户在 5 分钟内跑起来。
