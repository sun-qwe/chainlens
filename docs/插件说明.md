# dsh-pentest 插件说明

> 项目：ChainLens · DSH 探索链路数据可视化（本科毕业设计）
> 版本：dsh-pentest 0.1.0 ｜ 契约：`docs/00-设计规格.md` 第 3、4 节 + `data/schema/chain.schema.json`
> 本文只说明**如何安装、使用与验证**；本项目不把插件安装到正在运行的 DSH 配置中。

---

## 1. 这是什么 / 不是什么

`dsh-pentest` 是一个 **只做结构化记录** 的 DSH（Cordis 体系）最小插件：

- 把渗透测试智能体在**授权或仿真场景**中的探索过程（资产、服务、漏洞、凭据、会话、证据、动作）
  以 JSON Lines 事件链持久化到 `<数据目录>/engagements/<ENG-ID>/chain.jsonl`；
- 提供 4 个可选工具：开始/记录/结项/demo 生成；
- 提供 2 个只读 HTTP 路由（宿主支持时），供可视化端读取链路。

它**不是**攻击工具：插件本身不发起任何网络扫描/攻击请求，不执行系统命令，不内置漏洞利用代码；
所有演示数据均为仿真生成且已脱敏，目标地址限定在 RFC1918 私网、回环与 `.test` 保留域。

安全边界（强制实现，见 `lib/schema.js`、`lib/index.js`）：

| 约束 | 实现 |
|---|---|
| 记录 API 必须有授权依据 | `pentest_start_engagement` 校验 `authorization_basis` 非空（≥4 字符），否则拒绝 |
| scope 守卫 | 私网/回环/`.test`/`LAB-*` 直接通过；公网目标仅 `mode:"simulation"` 放行并提示，`mode:"authorized"` 一律拒绝 |
| 敏感值不入库 | `pentest_record_step` 写入前递归检测 `password/token/cookie/secret/*_key` 等键并替换为 `[REDACTED]`；`credential` 节点的 `props.value` 强制脱敏 |
| 只记录不执行 | 插件无 `fetch/http/net/dns/child_process` 调用；`pentest_demo` 只做本地内存生成与写文件 |
| JSONL 只追加 | 结项信息写文件末尾的 `note` 记录 + 独立 `summary.json`，不改写已有行 |

## 3. 安装到用户 DSH（文档与步骤，不改运行中的 DSH）

> ⚠️ 本文档不包含“自动安装”脚本对运行中 DSH 的写入。真实安装前请先备份 DSH 配置，
> 并确认 `dsh-pentest` 目录与 `data/` 数据来自本项目（离线、无第三方依赖）。

1. **复制插件目录**（不要复制 `node_modules`，本插件没有依赖）：
   ```powershell
   # 以 DSH 用户插件目录为例（不同 DSH 版本的插件目录可能不同，请以宿主文档为准）
   Copy-Item -Recurse .\dsh-pentest "$env:USERPROFILE\.dsh\plugins\dsh-pentest"
   ```
2. **注册插件补丁**：宿主启用 `dsh.bundle.patch`（即 `cordis.patch.yml`）后，无需手工改代码；
   或按宿主插件管理界面选择本地插件目录 `dsh-pentest`。补丁内容：
   ```yaml
   - insert:
       - id: dsh-pentest
         name: dsh-pentest
   ```
3. **重启/重载宿主后验证**：
   - 工具列表中应出现 `pentest_start_engagement`、`pentest_record_step`、
     `pentest_finish_engagement`、`pentest_demo`（4 个）；
   - 若宿主提供 Web 服务，只读路由（宿主支持时）为
     `GET /plugins/dsh-pentest/engagements` 与
     `GET /plugins/dsh-pentest/engagements/:id/chain`。
4. **数据目录**（优先级从高到低）：
   - 插件配置 `dataDir`；
   - 环境变量 `DSH_PENTEST_DATA_DIR`；
   - `$DSH_HOME/pentest`，否则 `~/.dsh/pentest`。
5. **卸载**：从宿主插件列表移除 `dsh-pentest` 并删除插件目录；**数据目录请保留/归档**，
   JSONL 是可视化端的输入，不建议删除。

> 普通 Node 环境（没有 `@deepseek-ai/dsh-tools`）也能 `import "dsh-pentest"` 成功：
> 工具注册采用 `try/catch + 动态 import`，失败只记录原因、不影响插件加载；此时 CLI 与
> `scripts/mock-host.mjs` 仍可完整使用。

### 3.1 插件配置（可选）

`apply(ctx, config)` 的 `config` 支持：

| 配置 | 类型 | 说明 |
|---|---|---|
| `dataDir` | string | 覆盖数据目录 |
| `operator` | string | 默认记录者标识（如 `operator:sun`），未传时用 `operator:local` |
| `quiet` | boolean | 静默模式（不打印提示日志） |
| `now` | `() => string \| number` | 时间源注入（测试用；返回 ISO 时间或毫秒时间戳） |
| `scenario` | string | 写入 meta 的场景标识（可选） |
| `toolkit` | object | 测试/宿主注入的 `{ defineTool }`（普通使用无需设置） |

> 规格 4.2 中的 `Config` 为可选项：为保证零依赖与 Cordis 兼容性，本包不导出 schemastery 形式的
> `Config`，配置在 `createPluginState`/`apply` 中做运行时校验（非法值不会被静默吞掉）。

## 4. 工具 API（宿主注册时）

### 4.1 `pentest_start_engagement`

入参：`{ name, mode, scope[], authorization_basis, expires_at?, description? }`

- `mode`：`simulation`（仅记录仿真）或 `authorized`（已获书面授权）；
- `authorization_basis`：必填，写明授权文书名称+编号；
- `scope`：CIDR / 域名 / URL / `LAB-*` 标识；授权模式禁止公网目标；
- 返回：`{ ok, engagement_id, data_dir, chain_file, started_at, warnings? }`，并向
  `chain.jsonl` 写入 `seq=1` 的 `meta`。

### 4.2 `pentest_record_step`

入参：`{ kind: "node"|"edge"|"event"|"evidence"|"note", data: object }`

- 自动补 `schema/seq/ts/source`，`id` 可省略（按类型自动编号：`host-001`、`svc-001`…）；
- 递归脱敏后再做字段校验，校验失败返回 `{ ok:false, error }` 并**不落盘**；
- 返回：`{ ok, seq, id, redacted, redacted_paths, warnings }`（引用暂不存在的对象只告警）。

示例（node）：

```json
{
  "kind": "node",
  "data": {
    "type": "host", "label": "WEB-DMZ-01", "stage": "recon", "risk": 5.5,
    "props": { "ip": "10.20.10.15", "os": "Ubuntu 22.04", "exposure": "dmz" }
  }
}
```

### 4.3 `pentest_finish_engagement`

无入参。追加一条结项 `note`（不改写历史行）并写
`engagements/<ENG-ID>/summary.json`（含 `ended_at`、统计与关键路径）。
返回：`{ ok, engagement_id, ended_at, summary_path, records, stats }`。

### 4.4 `pentest_demo`

入参：`{ scenario: "campus-lab"|"corp-ad"|"cloud-k8s", out?: string }`

- 固定 seed 生成仿真数据（**无任何网络行为**），默认写到 `<dataDir>/demo/<scenario>.jsonl`；
- 返回：`{ ok, scenario, file, stats }`；同一版本重复生成字节级一致。

### 4.5 只读路由（宿主支持时）

- `GET /plugins/dsh-pentest/engagements` → `{ schema:"dsh-pentest/engagements@1", data_dir, engagements[] }`
- `GET /plugins/dsh-pentest/engagements/:id/chain` → `{ schema:"dsh-pentest/chain-response@1", engagement_id, stats, warnings, records }`

路由 API 由宿主 `ctx.webServer.get`（或 `route("GET", …)`）适配；注册失败只记录原因，不影响插件加载。

## 5. 命令行（无需 DSH 即可用）

```powershell
cd dsh-pentest

# 生成单个场景（默认写 ../data/scenarios/<id>.jsonl）
node bin/dsh-pentest.mjs demo --scenario campus-lab

# 生成三个场景 + data/manifest.json（统计由实际数据计算）
node bin/dsh-pentest.mjs demo --all

# 校验 JSONL（契约 schema + seq/时间/引用/脱敏），0=通过 1=失败
node bin/dsh-pentest.mjs validate ../data/scenarios/campus-lab.jsonl

# 统计（默认输出 JSON；--json 输出机器可读格式）
node bin/dsh-pentest.mjs stats ../data/scenarios/cloud-k8s.jsonl --json

# 帮助 / 版本
node bin/dsh-pentest.mjs --help
node bin/dsh-pentest.mjs --version
```

退出码：`0` 成功；`1` 校验失败；`2` 用法错误。
`demo --all` 写入 `data/manifest.json`（`schema: dsh-pentest/dataset@1`），
`generated_at` 固定为常量以保证可复现。

## 6. 数据目录与文件

```
<数据目录>/
└─ engagements/
   └─ ENG-2026-001/
      ├─ chain.jsonl     # 首行 meta；seq 从 1 连续；ts 非递减；只追加
      └─ summary.json    # 结项摘要（pentest_finish_engagement 生成）
```

- JSONL 为 UTF-8（无 BOM）、行尾 `\n`、每行一个 JSON 对象；
- 记录公共字段：`schema/seq/ts/kind/source/actor/tags`；
- `kind`：`meta`（首行唯一）/`node`/`edge`/`event`/`evidence`/`note`；
- 字段级约束以 `data/schema/chain.schema.json` 为准；`validate` 会同时执行该 JSON Schema 与内置语义校验；
- 数据可复现：同一场景用固定 seed 生成，重复生成的字节级一致（测试覆盖）。

仓库内已生成三个场景（由 `demo --all` 产生，统计来自实际数据）：

| 场景 | 文件 | 规模 | 记录/节点/边/事件/证据 |
|---|---|---|---|
| `campus-lab` | `data/scenarios/campus-lab.jsonl` | small | 150 / 66 / 51 / 25 / 5 |
| `corp-ad` | `data/scenarios/corp-ad.jsonl` | medium | 450 / 180 / 150 / 105 / 12 |
| `cloud-k8s` | `data/scenarios/cloud-k8s.jsonl` | large | 900 / 260 / 320 / 300 / 17 |

> 统计字段口径与 `tools/chain-check.mjs` 一致：`stages` 为事件覆盖阶段数，
> `vulns` = `vulnerability` + `finding` 节点数。

## 8. 已知限制

1. `@deepseek-ai/dsh-tools` 不在本仓库依赖内：真实 DSH 宿主若未提供该包，
   工具注册会被安全跳过（插件仍可加载，CLI/mock-host 不受影响）。
2. 只读路由按宿主 `ctx.webServer` 的 `get`/`route` 两种常见形态适配；
   宿主 API 不同则自动降级（返回 `{ mounted:false, reason }`）。
3. JSONL 追加在**单进程内**通过 Promise 队列串行化；多进程同时写同一文件不在支持范围
   （数据采集插件的典型部署为单宿主单进程）。
4. 敏感字段检测按**键名**递归脱敏（另加疑似真实密钥/口令的字符串体检），
   无法识别藏在纯文本散文里的所有敏感值；真实使用仍需人工复核。
5. 数据为仿真演示，CVE 编号仅用于说明仿真环境复现的漏洞类型，不代表真实攻击成功。

## 9. 一个最小的宿主侧使用流程

```text
1) pentest_start_engagement { name:"XX 靶场授权测试", mode:"simulation",
                              scope:["10.20.10.0/24","lab.test"],
                              authorization_basis:"《靶场使用授权书》LAB-2026-017" }
2) pentest_record_step { kind:"node", data:{ type:"host", label:"WEB-01",
                                             stage:"recon", props:{ ip:"10.20.10.15" } } }
3) pentest_record_step { kind:"event", data:{ stage:"recon", action:"port_scan",
                                              summary:"对 WEB-01 执行端口扫描",
                                              result:"success", node_ids:["host-001"] } }
4) pentest_finish_engagement {}
5) 可视化端读取 <dataDir>/engagements/ENG-2026-001/chain.jsonl
```

所有记录只写本地 JSONL；插件不会替你执行任何扫描动作。
