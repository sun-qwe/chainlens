# ChainLens 设计规格 v1（冻结契约）

> 项目：DSH 插件 dsh-pentest 的探索链路数据可视化工具（本科毕业设计）
> 本文件是插件端与可视化端的唯一契约。两端实现必须严格遵守；任何字段变更由 Lead 统一修改本文件并通知双方。
> 工作目录：`D:\桌面2\dsh-c`

## 1. 背景与边界

DSH（DeepSeek Harness）是支持 Cordis 插件体系的智能体宿主。毕设题目要求围绕假想的 `dsh-pentest` 插件产生的"探索链路数据"做可视化分析工具。经检索本机 DSH 安装包、检出目录与本地插件目录，**均不存在 dsh-pentest 插件，也不存在公开的数据格式**。因此本项目采用「自建最小数据采集插件 + 自包含可视化工具」的方案：

1. `dsh-pentest`：一个**只做结构化记录、不内置任何攻击能力**的最小 DSH 插件。它在授权/仿真场景下，把渗透测试智能体的探索过程（资产、服务、漏洞、凭据、会话、证据、动作）以 JSONL 事件链持久化。
2. `ChainLens`：一个零依赖、纯前端（HTML/CSS/JS + SVG/Canvas）的可视化分析工具，读取 JSONL 探索链路，提供总览、链路图、时间轴回放、ATT&CK 覆盖矩阵、发现与证据、分析报告等视图。

**安全与合规边界（贯穿实现与论文）：**

- 插件与工具均不发起任何网络扫描/攻击请求；所有演示数据必须是**仿真生成、已脱敏**的数据，目标地址一律使用 RFC1918 私网 / 回环 / `.test` 保留域。
- 插件记录 API 强制要求 `authorization.basis` 非空；对公网目标只允许 `mode: "simulation"`（仅记录，不执行）。
- 原始口令、Cookie、Token、私钥等敏感值禁止入库：插件递归检测并脱敏为 `[REDACTED]`；可视化端对 `sensitive: true` 的证据默认打码。
- 论文中明确说明：系统是"过程记录与可视化分析工具"，不是攻击工具；真实使用必须取得书面授权并在隔离靶场进行。

## 3. 数据格式 v1（JSONL）

### 3.1 文件与行

- 文件为 UTF-8（无 BOM）JSON Lines，每行一个 JSON 对象，行尾 `\n`，空行忽略。
- 每行公共字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | string | 是 | 固定 `"dsh-pentest/chain@1"` |
| `seq` | integer ≥1 | 是 | 文件内严格递增，从 1 开始 |
| `ts` | string(date-time) | 是 | ISO 8601 带时区偏移，如 `2026-11-01T09:30:00+08:00` |
| `kind` | enum | 是 | `meta` / `node` / `edge` / `event` / `evidence` / `note` |
| `source` | enum | 否 | `plugin` / `simulation` / `import`，默认 `plugin` |
| `actor` | string | 否 | 记录者/执行者，如 `agent:planner`、`operator:sun` |
| `tags` | string[] | 否 | 自由标签，≤10 个，每个 ≤32 字符 |

- 首行必须是 `kind:"meta"`；全文件只允许一条 meta。
- `ts` 除 meta 外整体非递减；允许相等。时间倒序由导入端报 warning。
- 未知字段允许存在（向前兼容），可视化端应原样保留但可不展示。
- 数据字典与字段级约束以 `data/schema/chain.schema.json` 为准；本文件的表格是摘要。

### 3.2 `meta`（engagement 元数据）

```json
{
  "schema": "dsh-pentest/chain@1", "seq": 1, "kind": "meta",
  "ts": "2026-11-01T09:00:00+08:00",
  "source": "simulation",
  "engagement": {
    "id": "ENG-2026-001",
    "name": "星海大学 Web 靶场授权测试",
    "mode": "simulation",
    "scope": ["10.20.10.0/24", "lab.starhai.test"],
    "authorization": {
      "basis": "《网络安全实训靶场使用授权书》（编号 LAB-2026-017）",
      "expires_at": "2026-12-31T23:59:59+08:00"
    },
    "operator": "孙博奥",
    "team": ["红队 A 组"],
    "started_at": "2026-11-01T09:00:00+08:00",
    "ended_at": null,
    "description": "针对实训靶场 DMZ 与内网办公段的授权测试，全程在隔离网络中进行。"
  },
  "tool": { "name": "dsh-pentest", "version": "0.1.0" },
  "scenario": "campus-lab"
}
```

约束：`mode` ∈ `simulation` / `authorized`；`scope` 至少 1 项；`authorization.basis` 非空；`started_at` ≤ 后续所有时间。

### 3.3 `node`（探索链路节点）

```json
{
  "schema": "dsh-pentest/chain@1", "seq": 12, "kind": "node",
  "id": "host-003", "ts": "2026-11-01T09:12:00+08:00",
  "type": "host", "label": "WEB-DMZ-01",
  "stage": "recon", "risk": 6.5, "confidence": 0.92,
  "props": { "ip": "10.20.10.15", "os": "Ubuntu 22.04", "exposure": "dmz", "critical": true },
  "attck": { "tactic": "TA0007", "technique": "T1046", "name": "Network Service Discovery" },
  "tags": ["dmz", "web"]
}
```

- `id`：`^[a-z][a-z0-9-]{1,63}$`，全局唯一。
- `type` ∈ `target`（目标组织）/`host`（主机）/`service`（服务）/`webapp`（Web 应用）/`endpoint`（接口）/`vulnerability`（漏洞）/`credential`（凭据）/`session`（会话/权限）/`data`（数据/证据）/`finding`（风险发现）。中文映射见 3.8。
- `stage` ∈ 见 3.6。
- `risk`：0–10，默认 0；`confidence`：0–1，默认 1。
- `props`：自由对象，建议字段见 3.4。
- `attck`：可选，`tactic` 为 TAxxxx，`technique` 为 Txxxx，`name` 英文名。

### 3.4 各类型节点的建议 `props`

| type | 建议 props |
|---|---|
| target | `industry`、`domain`、`region`、`owner` |
| host | `ip`、`hostname`、`os`、`exposure`（internet/dmz/intranet）、`critical`、`owner` |
| service | `port`、`protocol`、`product`、`version`、`banner` |
| webapp | `url`、`tech`（框架/中间件数组）、`auth`（登录方式） |
| endpoint | `method`、`path`、`params`、`auth_required` |
| vulnerability | `severity`（critical/high/medium/low/info）、`cvss`（0–10）、`cve`、`category`（OWASP 分类）、`status`（confirmed/suspected）、`recommendation`、`description` |
| credential | `account`、`kind`（password/hash/ticket/token）、`privilege`、`source`；**禁止原始口令**，值为 `[REDACTED]` |
| session | `user`、`privilege`、`host_id`、`valid_until` |
| data | `kind`（file/db/dump/config）、`classification`（public/internal/confidential）、`path` |
| finding | `severity`、`title`、`impact`、`recommendation`、`status`（open/fixed/accepted） |

### 3.5 `edge`（关系）

```json
{
  "schema": "dsh-pentest/chain@1", "seq": 36, "kind": "edge",
  "id": "rel-018", "ts": "2026-11-01T09:40:00+08:00",
  "from": "vuln-004", "to": "sess-002",
  "relation": "exploits", "stage": "initial_access",
  "weight": 0.86,
  "props": { "evidence_id": "evd-006" },
  "attck": { "tactic": "TA0001", "technique": "T1190", "name": "Exploit Public-Facing Application" }
}
```

- `relation` ∈ `resolves_to`（解析）/`exposes`（暴露）/`runs_on`（运行于）/`routes_to`（路由到）/`has_vuln`（存在漏洞）/`exploits`（利用）/`grants`（授予权限）/`pivots_to`（横向移动）/`accesses`（访问）/`evidences`（佐证）/`belongs_to`（归属）。
- `from` / `to` 必须引用已存在的 node id（全文件范围即可，允许后出现）。
- `weight`：0–1，默认 1。

### 3.6 `event`（时间轴动作，回放最小粒度）

```json
{
  "schema": "dsh-pentest/chain@1", "seq": 40, "kind": "event",
  "id": "evt-021", "ts": "2026-11-01T09:44:00+08:00",
  "stage": "initial_access", "action": "exploit_confirmed",
  "summary": "确认 /api/v2/export 存在未授权访问，可导出用户列表",
  "result": "success", "risk": 7.2,
  "node_ids": ["vuln-004", "sess-002"], "edge_ids": ["rel-018"],
  "detail": "使用只读 GET 请求验证，未修改任何数据；证据见 evd-006。",
  "duration_ms": 185000,
  "actor": "agent:executor"
}
```

- `action`：snake_case，2–64 字符，如 `port_scan`、`service_fingerprint`、`dir_enum`、`vuln_verify`、`exploit_confirmed`、`credential_reuse`、`privilege_escalation`、`lateral_move`、`evidence_collect`、`report_finding`。
- `result` ∈ `success` / `failure` / `partial` / `info`。
- `risk`：0–10。
- `node_ids` / `edge_ids` 为相关对象引用；可视化端用于回放时点亮对象。

### 3.7 `evidence` / `note`

```json
{ "schema": "dsh-pentest/chain@1", "seq": 41, "kind": "evidence", "id": "evd-006",
  "ts": "2026-11-01T09:44:30+08:00", "type": "http",
  "node_id": "vuln-004", "title": "未授权导出接口响应（已脱敏）",
  "summary": "HTTP 200，返回 37 条用户记录字段名；正文已裁剪。",
  "hash": "sha256:9f2c...", "path": "evidence/ENG-2026-001/evd-006.txt",
  "sensitive": true }
```

- `type` ∈ `screenshot` / `http` / `config` / `log` / `file` / `credential` / `note`。
- `sensitive: true` 时前端只显示标题与"已脱敏"，不展示 summary。
- `note`：`{ id, ts, content, node_ids? }`，人工批注或思路记录，不算 event。

## 4. dsh-pentest 插件规格（plugin-dev）

### 4.1 包与文件

```
dsh-pentest/
├─ package.json          # name:"dsh-pentest", version:"0.1.0", type:"module", main:"lib/index.js",
│                        # exports {".":...,"./cordis.patch.yml":...}; dsh.bundle.patch; files 白名单
├─ cordis.patch.yml      # - insert: [{ id: dsh-pentest, name: dsh-pentest }]
├─ README.md             # 安装、工具、权限边界（中文）
├─ lib/index.js          # cordis 插件：export name / apply / Config(可选)
├─ lib/schema.js         # 记录构造 + 校验 + 脱敏（与 chain.schema.json 对齐）
├─ lib/store.js          # 目录/JSONL 追加/原子写/读取
├─ lib/simulator.js      # 仿真链路生成器（确定性 PRNG）
├─ lib/scenarios.js      # 3 个场景的资产/漏洞/事件蓝本
├─ bin/dsh-pentest.mjs   # CLI
├─ scripts/mock-host.mjs # 用 mock ctx 验证插件能加载、工具注册、记录落盘
└─ tests/*.test.mjs      # node:test
```

### 4.2 插件 API（cordis）

- `export const name = "dsh-pentest"`；`export function apply(ctx, config = {})`。
- 数据目录：`process.env.DSH_PENTEST_DATA_DIR` 优先，否则 `path.join(process.env.DSH_HOME || os.homedir()+"/.dsh", "pentest")`；子目录 `engagements/<engagementId>/chain.jsonl`。
- 若 `ctx.tools?.register` 与可解析的 `@deepseek-ai/dsh-tools` 同时存在，注册以下工具（用 `defineTool`）；**必须用 try/catch + 动态 import 保证在普通 Node 环境也能加载插件**：
  1. `pentest_start_engagement`：入参 `{ name, mode, scope[], authorization_basis, expires_at?, description? }`，返回 `{ engagement_id, data_dir }`；scope 校验（私网/回环/`.test`/`LAB-*`），mode=authorized 时 scope 不得含公网地址；authorization_basis 必填。
  2. `pentest_record_step`：入参 `{ kind: "node"|"edge"|"event"|"evidence"|"note", data: object }`，自动补 `schema/seq/ts` 并脱敏，追加落盘，返回 `{ seq, id }`。
  3. `pentest_finish_engagement`：写 `ended_at`（以最后一条记录重写 meta？JSONL 不允许改行，可在文件末尾追加 `kind:"note"` 结项标记 + 单独 `summary.json`）。
  4. `pentest_demo`：入参 `{ scenario: "campus-lab"|"corp-ad"|"cloud-k8s", out?: string }`，生成仿真数据（无网络行为），返回文件路径。
- 若 `ctx.webServer` 可用，尝试注册只读路由（失败不影响加载）：`GET /plugins/dsh-pentest/engagements`、`GET /plugins/dsh-pentest/engagements/:id/chain`。路由实现放独立函数，用 mock 测试。
- 插件不得发起网络请求、不得执行系统命令（CLI 除外且只读写本地文件）。

### 4.3 CLI（无 DSH 也可用）

```
node bin/dsh-pentest.mjs demo --scenario campus-lab --out ../data/scenarios/campus-lab.jsonl
node bin/dsh-pentest.mjs demo --all --out ../data/scenarios
node bin/dsh-pentest.mjs validate <file.jsonl>
node bin/dsh-pentest.mjs stats <file.jsonl>
node bin/dsh-pentest.mjs assistant ...   # 可选：交互式记录小工具
node bin/dsh-pentest.mjs --help
```

- `demo --all` 生成 3 个场景并写 `data/manifest.json`（统计由实际数据计算）。
- `validate` 输出错误/警告列表，退出码 0/1。
- 数据必须**确定性**：固定 seed（如 campus-lab=20261101），同一版本重复生成字节级一致（时间戳也要固定，便于测试/论文可复现）。

### 4.4 测试要求（node:test）

- schema：合法记录通过；缺字段/非法枚举/重复 id/错误引用被拒绝或警告。
- 脱敏：嵌套 props 中的 `password/token/cookie/secret/key` 值被替换为 `[REDACTED]`。
- scope 守卫：公网地址被拒绝；私网通过。
- store：并发/重复追加不破坏 JSONL；seq 递增。
- simulator：3 个场景都能生成，记录数/节点/边/事件>0；固定 seed 两次生成内容一致；通过 schema 校验。
- mock-host：插件 `apply()` 在 mock ctx 下不抛错；工具注册被调用；生成的 JSONL 可被可视化端解析（用 `data/schema/chain.schema.json` 或共享校验器）。
- 运行：`cd dsh-pentest && node --test tests/`。

### 4.5 交付数据

- `data/scenarios/campus-lab.jsonl`（小，~70 节点、~150 记录）
- `data/scenarios/corp-ad.jsonl`（中，~180 节点、~450 记录）
- `data/scenarios/cloud-k8s.jsonl`（大，~260 节点、~900 记录，用于性能实验）
- `data/manifest.json`

## 5. ChainLens 可视化端规格（viz-dev）

### 5.1 技术与约束

- 纯静态：`visualizer/index.html` + ES modules；**零第三方依赖、零构建、零网络请求**（字体用系统字体）。
- 现代 Chrome/Edge 可用即可；同时兼顾 1366×768 投影演示。
- 所有数据经 `data.js` 归一化：`{ meta, nodes[], edges[], events[], evidences[], notes[], warnings[], stats }`；解析 JSONL 或 JSON 数组。
- 支持 URL 深链（用于论文截图与自动测试）：
  `#/overview?scenario=campus-lab`
  `#/graph?scenario=corp-ad&cursor=120&critical=1&focus=vuln-007&filter=stage:initial_access,type:vulnerability`
  `#/timeline?scenario=campus-lab&cursor=50`
  `#/attack?scenario=cloud-k8s`
  `#/findings?scenario=campus-lab&severity=high,critical`
  `#/report?scenario=campus-lab`
  `#/about`（可选：项目说明、数据规范摘要）
- 页面加载：读取 `../data/manifest.json` → 默认第一个场景；失败时展示导入界面 + 内置 fallback 数据（可用 `js/fallback-data.js` 存 20 条左右最小样例）。
- 错误处理：单条坏行跳过并累计 warning；致命错误显示可操作的空态。控制台无未捕获异常。
- 可测试性：挂 `window.ChainLens = { app, data, analytics, layout }`；提供 `window.__chainlensReady` Promise 与 `window.__chainlensState` 快照，供自动测试。

### 5.2 信息架构

顶栏（56–64px）：Logo「ChainLens · 探索链路可视化」、场景选择器、视图 Tab、导入按钮、导出菜单、主题切换（可选）、帮助。
主体：左侧筛选栏 260px（搜索、阶段、节点类型、严重度、结果状态、快捷键提示）；中央视图；右侧详情抽屉 380px（点击节点/事件/证据时滑出，可关闭）。
底部回放条（链路图/时间线视图）：播放/暂停、上一事件/下一事件、进度滑杆、当前事件摘要、速度 0.5×/1×/2×/4×、时间戳。
空态/加载态/错误态统一设计；toast 提示。

### 5.3 各视图要求

**A. 总览 `#/overview`**
- Hero 区：场景名称、授权依据、目标范围、起止时间、模式徽标、数据质量分。
- KPI 卡 6 个：节点总数、关系数、事件数、漏洞/发现数（按严重度分布）、证据数、关键路径风险（附阶段覆盖）。
- 图表：阶段分布（横向条形，含该阶段节点/事件数）、严重度环图、时间密度（按 10 分钟桶的柱状图）、节点类型 Top 排行、ATT&CK 技战术覆盖数。
- 「链路摘要」：关键路径节点串（可点击跳转链路图并高亮）、Top 5 风险节点、最近 8 条事件。
- 交互：KPI 卡可点击跳转对应视图/筛选。

**B. 链路图 `#/graph`**
- 自定义 SVG 图层：7 个阶段列（顶部列标题）、节点卡片（图标+标签+类型徽标+风险条）、边（贝塞尔曲线+箭头，按 relation 着色/虚线）、hover tooltip、点击选中→详情抽屉。
- 布局算法（必须自己实现，写入论文）：阶段约束分层 + 重心法排序（≥4 轮）+ 同层轻量力松弛；提供「分层视图 / 力导向视图」切换（力导向可用简单 Fruchterman-Reingold，300 次迭代，确定性种子）。
- 交互：缩放（滚轮/按钮，限制 0.3–2.5×）、平移（拖拽空白）、节点拖拽（临时固定，双击释放）、重置视图、适配屏幕；筛选后重排（动画）；搜索定位；邻居聚焦（选中节点时高亮 1 跳邻居）；关键路径高亮（红色虚线动画）；回放（按 cursor 渐进显示节点/边，新增节点脉冲，当前事件对应的节点/边高亮）。
- 边标签 hover 显示 relation 中文；节点 label 过长省略，hover 全名。
- 性能：260 节点/500 边场景下首次渲染 < 1s（1366 笔记本），交互 60fps 目标；超 600 节点时自动简化（隐藏边标签、降低动画）。

**C. 时间线 `#/timeline`**
- 横向时间轴（SVG）：7 条阶段泳道；事件按时间落点，颜色按 result/risk；缩放时间范围（浏览器宽度自适应 + 时间范围滑块可选）；鼠标 hover 显示事件卡；点击滚动并打开详情；播放游标随回放移动；关键事件（成功利用/获得会话/发现高危）放大标记。
- 上方统计：各阶段耗时、事件成功率、最长静默间隔。
- 与链路图共享 cursor 状态（切换视图保留）。

**D. ATT&CK 矩阵 `#/attack`**
- 以 tactic 为列、technique 为行（只显示数据中出现的），单元格显示事件计数热力色；点击单元格筛选事件列表；右侧/下方列出命中事件；顶部覆盖指标（tactics 覆盖 x/12、techniques 数）。
- 无 attck 数据时给出空态说明。

**E. 发现与证据 `#/findings`**
- 两个 Tab：「风险发现」（vulnerability/finding 节点表：严重度、CVSS、标题、资产、阶段、状态、证据数；可排序/筛选/搜索）与「证据库」（evidence 表：类型、标题、关联节点、时间、sensitive 打码）。
- 行点击打开详情抽屉；支持导出 CSV（发现）/JSON（证据）。
- 汇总条：按严重度计数、已确认/疑似比例、有证据覆盖率。

**F. 分析报告 `#/report`**
- 文档式预览（白底/深色可打印），自动生成：报告信息、执行摘要、测试范围与授权、链路指标表、阶段推进、关键路径、Top 发现（含建议）、ATT&CK 覆盖、证据清单、数据质量说明。
- 按钮：打印/另存为 PDF（`window.print()`，配 @media print）、复制 Markdown、导出 JSON。
- 报告必须使用真实数据计算，不得出现占位符。

**G. 导入**
- 拖拽或选择 `.jsonl/.json`；解析后成为「自定义场景」并自动切换；显示校验结果（错误/警告数量、可展开明细）。
- 导入的数据不写入磁盘（除非用户下载导出）；刷新后恢复默认数据（可接受）。

### 5.4 设计系统（必须体现完成度）

- 深色主题：背景 `#070b14`，面板 `#0d1524`，边框 `#1e2a44`，文字 `#e6edf7`，次文字 `#8da2c0`；强调青 `#22d3ee`、紫 `#8b5cf6`、橙 `#f59e0b`；危险红 `#ef4444`、成功绿 `#10b981`。
- 细节：背景径向渐变 + 极淡网格；卡片 1px 边框 + 内发光；数字用 `font-variant-numeric: tabular-nums`；标题字重 600；圆角 10–14px；阴影克制。
- 动效 150–300ms（`prefers-reduced-motion` 时关闭）；节点出现脉冲、路径流动虚线、抽屉滑入、数字滚动。
- 中文字体：`"Microsoft YaHei UI", "PingFang SC", "Segoe UI", system-ui, sans-serif`；英文/数字可用 `"Segoe UI"`。
- 图标：内联 SVG symbol sprite（不引外部库）。
- 可访问性：按钮有 aria-label，抽屉 Esc 关闭，焦点环可见，颜色对比 ≥ 4.5:1（正文）。

### 5.5 前端分析算法（写入论文）

- 数据归一化与校验：JSONL 解析、schema 语义校验、引用完整性、重复 id、时间单调性、敏感字段检测；输出 errors/warnings/info 与质量分 `max(0, 100 - 8*errors - 2*warnings)`。
- 指标计算（必须有单元测试）：
  - `nodeTypeCounts`、`stageCounts`、`severityCounts`
  - `durationMs = lastEvent.ts - firstEvent.ts`
  - `stageDurationMs`：相邻阶段的第一个事件时间差（或按事件时间跨度）
  - `criticalPath`：仅使用 `stage(from) < stage(to)` 的前向边（同阶段按 ts 先后），节点权重 `1 + risk`，DAG 上 DP 求最长路径；返回 `{nodes, edges, score, stages}`；若无前向边则回退为最大风险节点。
  - `attackCoverage`：tactic/technique 去重计数
  - `evidenceCoverage`：有证据的 vulnerability/finding 占比
  - `riskScore`：所有 vulnerability/finding 的 `severity` 加权（critical=10, high=7, medium=4, low=1, info=0.2）× confidence，保留一位小数
  - `dataQuality` 同上
- 布局：`layoutLayered(nodes, edges, opts)` 返回 positions；`layoutForce` 返回 positions；两者都确定性（固定迭代次数，无 `Math.random` 或使用种子 PRNG）。
- 回放：`events` 按 ts 排序；`visibleState(cursor)` 返回可见 node/edge id 集合与当前事件；播放节奏基于事件间隔的归一化映射（最小 350ms，最大 1400ms，除以 speed）。
