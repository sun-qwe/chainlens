# ChainLens 系统设计

> 本文档记录系统的设计决策与关键算法，供论文第 4 章、答辩与后续维护使用。契约细节以 `docs/00-设计规格.md`、`data/schema/chain.schema.json` 为准。

## 1. 设计目标与原则

ChainLens 面向 DSH（DeepSeek Harness）生态中 `dsh-pentest` 插件产生的探索链路数据，解决三个问题：**过程不可见、数据不可读、结论不可复现**。设计目标如下：

1. **可解释**：把分散在工具调用、时间戳、资产、漏洞、证据中的探索过程还原为一张可追溯的链路图与一条可回放的时间线。
2. **可复现**：以纯文本 JSONL 作为唯一事实来源，任何视图都由同一份数据确定性推导，便于复现实验与审计。
3. **可扩展**：数据格式向前兼容，新增节点类型/关系类型不影响旧数据；可视化视图按模块拆分，便于扩展新视图。
4. **安全合规**：工具只记录、不攻击；样例数据全部为仿真/脱敏数据；敏感字段在采集端和展示端双重防护。
5. **零依赖可交付**：前端不依赖第三方图表库与构建工具，双击本地服务即可演示，降低答辩现场环境风险。

设计遵循"**数据与视图分离**"原则：插件负责生产数据，可视化端只消费数据；分析算法以纯函数实现，与 DOM 解耦，便于单元测试与在论文中形式化描述。

## 2. 总体架构

系统采用四层架构：

```
┌─────────────────────────────────────────────────────────────┐
│  展示层 (Presentation)                                       │
│  总览仪表盘 │ 探索链路图 │ 时间线回放 │ ATT&CK 矩阵          │
│  发现与证据 │ 分析报告 │ 数据导入 │ 详情抽屉                │
├─────────────────────────────────────────────────────────────┤
│  分析层 (Analysis)                                           │
│  归一化校验 │ 图模型构建 │ 指标计算 │ 关键路径 │ 布局算法    │
│  ATT&CK 映射 │ 回放状态机 │ 数据质量评分                    │
├─────────────────────────────────────────────────────────────┤
│  数据层 (Data)                                               │
│  chain.jsonl（事件溯源） │ manifest.json │ JSON Schema        │
├─────────────────────────────────────────────────────────────┤
│  采集层 (Collection)                                         │
│  dsh-pentest 插件：工具注册 │ 记录构造 │ 授权/scope 守卫     │
│  脱敏 │ JSONL 存储 │ 仿真数据生成器 │ CLI                    │
└─────────────────────────────────────────────────────────────┘
```

- **采集层**运行在 DSH/Cordis 宿主内，通过 `defineTool` 向智能体暴露记录工具；也可以在无 DSH 的普通 Node 环境中通过 CLI 生成仿真数据。
- **数据层**是系统唯一事实来源：一次测试对应一个 `chain.jsonl`，文件头 `meta` 记录授权与范围，后续为按时间排列的 `node/edge/event/evidence/note` 记录。
- **分析层**由纯函数构成：解析、语义校验、图模型构建、指标、布局、关键路径、ATT&CK 覆盖、回放状态。
- **展示层**用 SVG 自绘所有图形，以路由（hash）驱动视图切换，以统一状态容器驱动筛选、回放、选中、详情抽屉。

## 3. 数据模型设计

### 3.1 事件溯源（Event Sourcing）

探索链路天然是"动作序列"：每一次扫描、验证、登录、提权、取证都是一个事件。系统采用事件溯源思想，以**追加写**的 JSONL 记录事实，而不是维护可变的关系表。优点：

1. 审计友好：记录只追加、不修改，天然保留完整历史；
2. 故障恢复：文件损坏时可按行恢复，单行错误不影响整体；
3. 可回放：事件序列直接对应时间轴，支持"回到某一时刻"的状态重建；
4. 流式处理：可边采集边展示，后续可扩展实时推送。

### 3.2 记录类型与职责

| 记录 | 职责 | 关键字段 |
|---|---|---|
| `meta` | 测试会话元数据、授权与范围 | engagement、tool、scenario |
| `node` | 链路中的实体（目标/主机/服务/漏洞/凭据/会话/数据/发现） | id、type、label、stage、risk、props、attck |
| `edge` | 实体之间的有向关系 | from、to、relation、stage、weight |
| `event` | 时间轴上的动作，回放的最小粒度 | id、ts、action、result、node_ids、edge_ids |
| `evidence` | 与节点关联的证据（脱敏） | node_id、type、title、sensitive |
| `note` | 人工批注与思路记录 | content、node_ids |

节点是"状态"，事件是"动作"，边是"关系"：一次动作可能创建节点（发现新资产）、创建边（建立关系）并产生事件（记录动作）。三者通过 id 与 `node_ids/edge_ids` 关联，形成有向异构图。

### 3.3 阶段与 ATT&CK 双层语义

链路阶段（stage）是一条线性推进的"探索进度轴"，用于布局分列和阶段统计；ATT&CK 战术/技术（tactic/technique）是安全语义标签，用于覆盖矩阵与风险评估。二者分离的原因：

- 阶段回答"测试进行到哪一步"，是过程视角；
- ATT&CK 回答"用了什么技战术"，是安全视角；
- 同一阶段可对应多个战术（如初始访问既可能是 T1190 漏洞利用，也可能是 T1078 有效账号），不能强行一一对应。

### 3.4 数据校验

导入端将校验分为三级：

- **error**：JSON 解析失败、必填字段缺失、枚举非法、id 重复、seq 不连续、边引用不存在、缺少 meta。error 记录不参与图构建，但会显示在错误面板。
- **warning**：时间倒序、孤儿引用（事件引用不存在的节点/边）、敏感字段未脱敏、自环边。warning 记录保留并展示，但不阻断。
- **info**：空 props、未知扩展字段等。

质量分公式：`quality = max(0, 100 - 8 × errors - 2 × warnings)`，用于总览页数据可信度提示。

## 4. dsh-pentest 插件设计

### 4.1 模块划分

```
lib/index.js       Cordis 插件入口：配置、apply、可选工具注册、可选 HTTP 路由
lib/schema.js      记录构造器、字段校验、递归脱敏、scope 守卫
lib/store.js       engagement 目录管理、JSONL 追加、读取、统计、原子写
lib/simulator.js   确定性仿真生成器（种子 PRNG）
lib/scenarios.js   三个场景的资产/漏洞/事件蓝本
bin/dsh-pentest.mjs  CLI：demo / validate / stats
```

### 4.2 记录生命周期

1. `pentest_start_engagement` 校验授权依据、mode、scope（仅私网/回环/保留域），创建 `ENG-*` 会话与目录；
2. `pentest_record_step` 接收 `kind + data`，补齐 `schema/seq/ts`，执行字段校验与敏感字段脱敏，追加写入 `chain.jsonl`；
3. `pentest_finish_engagement` 追加结项 note，并写 `summary.json`（不改写历史记录）；
4. `pentest_demo` 生成完全仿真的链路，不执行任何真实网络动作。

### 4.3 脱敏与安全守卫

- 递归遍历 `props`，命中 `password/passwd/pwd/token/cookie/authorization/secret/api_key/private_key` 等键名时替换为 `[REDACTED]`；
- 凭据节点的 `props.value` 强制为 `[REDACTED]`；
- scope 守卫：仅允许 RFC1918 私网、回环、`.test/.local/.invalid` 保留域、`LAB-*` 标识；`mode=authorized` 时拒绝公网目标；
- 插件不 import 网络模块、不执行命令，CLI 仅做本地文件读写。

### 4.4 仿真数据生成

仿真是本系统的"数据可得性"解决方案。生成器以固定 seed 驱动伪随机序列，按场景蓝本逐步生成：

1. 以攻击阶段为骨架，为每个阶段挑选若干"动作模板"；
2. 每个动作生成对应事件，并按概率创建节点与边；
3. 时间戳按动作耗时累加，保证单调；
4. 生成后执行与导入端一致的语义校验；
5. 输出排序后的 JSONL 与场景清单。

固定 seed + 固定时间基点的生成结果可以字节级复现，满足实验可复现性要求。

## 5. ChainLens 可视化端设计

### 5.1 模块划分

```
js/data.js        JSONL/JSON 解析、归一化、语义校验、质量评分
js/analytics.js   指标、关键路径、ATT&CK 覆盖、阶段统计、回放状态
js/layout.js      阶段分层布局、重心排序、力导向布局
js/ui.js          通用组件（图标、tooltip、抽屉、toast、弹窗、表格）
js/views/*.js     总览/链路图/时间线/ATT&CK/发现证据/报告
js/app.js         路由、状态容器、数据加载、导入、导出、bench
```

### 5.2 状态管理

采用单向数据流：

```
URL/交互事件 → dispatch(action) → state 更新 → render(state)
```

核心状态包括：`scenarioId`、`dataset`、`cursor`、`playing`、`filters`、`selectedNodeId`、`selectedEventId`、`focusMode`、`criticalPathVisible`、`activeView`。视图只读状态并派发动作，不直接修改数据。URL hash 与核心状态双向同步，保证深链可复现。

### 5.3 视图与交互

- **总览**：KPI + 阶段分布 + 严重度环图 + 事件密度 + Top 风险 + 关键路径摘要；
- **链路图**：7 阶段列，节点卡片按类型着色、按风险描边，边用贝塞尔曲线与箭头表示，支持缩放、平移、拖拽、筛选、搜索、邻居聚焦、关键路径高亮、回放渐进显示；
- **时间线**：7 条阶段泳道，事件按时间落点，播放游标同步滚动，显示阶段耗时与静默间隔；
- **ATT&CK 矩阵**：战术为列、技术为行的热力矩阵，点击联动筛选；
- **发现与证据**：可排序、可搜索、可导出 CSV/JSON，敏感证据默认打码；
- **分析报告**：基于当前数据实时生成的文档式报告，支持打印/另存 PDF。

### 5.4 深链约定

`#/view?scenario=<id>&cursor=<n>&critical=1&focus=<nodeId>&filter=<k:v,...>`。深链用于论文截图、自动验收与问题复现；`cursor` 同时决定回放位置与可见子图。

## 6. 关键算法设计

### 6.1 阶段约束分层布局

输入：节点集合 V、边集合 E、阶段序号函数 s(v) ∈ [0,6]。目标：同阶段节点同列，减少边交叉，保持图可读。

1. **分层**：`layer(v) = s(v)`；筛选后为空层折叠或压缩列宽；
2. **层内排序**：初始按节点类型优先级、风险降序排列；然后执行 k=4 轮重心法（barycenter）：
   - 正向：`pos(v) = mean(pos(u) for u ∈ pred(v))`，按值排序；
   - 反向：`pos(v) = mean(pos(w) for w ∈ succ(v))`，按值排序；
   - 对跨层边按层距离加权，避免远端边过度影响；
3. **坐标分配**：列宽 `COL_W`，行距 `ROW_H`，节点 y 坐标按排序序号居中；
4. **同层力松弛**（可选）：固定 x，对同层节点施加排斥力、对相邻层边施加弹簧力，迭代 18 次，步长递减；
5. **边路由**：正向边用三次贝塞尔曲线（控制点在源右侧/目标左侧），跨多列边加大曲率；反向边从节点下方绕行，避免与正向边混淆。

该算法属于 Sugiyama 分层布局的轻量变体：省略了虚拟节点与交叉最小化的精确求解，换来 O(k·(|V|+|E|)) 的可控复杂度，在 300 节点规模下毫秒级完成，适合浏览器端实时筛选重排。

### 6.2 风险加权关键路径

将链路图视为 DAG（仅保留 `stage(from) < stage(to)` 的前向边；同阶段按时间先后），节点权重 `w(v)=1+risk(v)`，求从入度为 0 到出度为 0 的最大权重路径：

```
dp[v] = w(v) + max{ dp[u] | (u,v) ∈ E' }
path[v] = argmax 的前驱
answer = max{ dp[v] | outdeg(v)=0 }
```

若存在环（异常数据），先用 DFS 标记回边并剔除；若无前向边，则回退为风险最高的单节点。关键路径用于回答"哪条链路贡献了最大风险"，是报告的核心结论之一。

### 6.3 ATT&CK 覆盖计算

遍历节点、边、事件的 `attck` 字段，按 `tactic` 分组去重 `technique`，统计每个技术出现次数（事件计数 + 关联对象计数加权），生成矩阵；覆盖率 = 出现战术数 / 12、出现技术数 / 数据中全部技术数。矩阵单元格点击后，按技术过滤事件列表。

### 6.4 回放状态机

事件按 ts 升序排列，游标 `cursor ∈ [0,N]`。可见集合：

```
visibleNodes = { n | n.ts ≤ events[cursor].ts }
visibleEdges = { e | e.ts ≤ events[cursor].ts }
```

播放时按事件间隔归一化推进：`delay = clamp(350ms, 1400ms, gapNormalized) / speed`；到达末尾自动停止。回放既可用于演示"测试过程如何推进"，也可用于定位某一时刻的链路状态。

### 6.5 数据质量评分

见 3.4。质量分在总览页与报告页展示，低于阈值时提示用户检查数据。

## 7. 接口设计

| 接口 | 形式 | 说明 |
|---|---|---|
| 插件工具 | DSH tool（可选） | start / record_step / finish / demo |
| CLI | `node bin/dsh-pentest.mjs <cmd>` | demo/validate/stats，无 DSH 也可运行 |
| 数据文件 | `chain.jsonl` + `manifest.json` | 唯一事实来源，UTF-8 JSON Lines |

| 前端深链 | URL hash | 视图 + 场景 + 回放位置 + 筛选 |
| 前端调试接口 | `window.ChainLens` | data/analytics/layout/bench |
| 截图服务 | `POST 127.0.0.1:8799/shot` | 仅本机，用于自动验收与论文插图 |

## 8. 安全与合规设计

1. **最小能力**：插件无扫描/利用能力，仅记录；样例数据全部仿真。
2. **授权前置**：记录前必须提供授权依据与范围；公网目标只允许仿真模式。
3. **双重脱敏**：采集端递归脱敏 + 展示端敏感标记打码。
4. **数据最小化**：样例只保留字段名与脱敏值，不包含真实个人信息。
5. **可审计**：JSONL 追加写、事件可回放；报告注明数据来源与仿真属性。
6. **合规声明**：论文与 README 明确系统使用边界，真实测试须取得书面授权并遵守《网络安全法》《数据安全法》与等级保护要求。

## 9. 部署视图

- **演示模式**：`python serve.py` 启动静态服务 → 浏览器打开 `http://127.0.0.1:8787/visualizer/`；无需安装依赖。
- **插件模式**：将 `dsh-pentest` 放入 DSH 本地插件目录并在 `cordis.patch.yml` 注册；智能体在授权会话中调用记录工具，数据写入 `$DSH_HOME/pentest/engagements/<id>/chain.jsonl`；ChainLens 通过导入或本地服务读取。
- **离线分析**：直接拖入 JSONL 文件，所有分析在浏览器本地完成，数据不出本机。

## 10. 设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 图表库 vs 自绘 | 自绘 SVG | 零依赖、可控、可写论文算法；规模 ≤ 600 节点足够 |
| 关系库 vs JSONL | JSONL | 追加写、可审计、可复现、跨语言；规模小无需数据库 |
| 实时采集 vs 事后导入 | 两者兼容 | 插件记录 + 导入分析，覆盖演示与分析两种场景 |
| 单一视图 vs 多视图 | 多视图联动 | 不同问题需要不同抽象：图看结构、时间线看过程、矩阵看技战术 |
| 真实数据 vs 仿真数据 | 仿真 + 可导入 | 题目数据源不存在；仿真保证可复现，导入保证可扩展 |
